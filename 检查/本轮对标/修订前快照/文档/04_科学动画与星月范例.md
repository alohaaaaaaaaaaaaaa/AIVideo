# 科学动画与星月范例

这套库把萧山片中真正用过、观众认可的制作方法保存下来：有依据的数据、能看懂的空间关系、连续完成的动作，以及跟着口播走的镜头。它不是 UFO 专用模板。调查黑客事件、金融骗局、工程事故时，复用的是这些方法；天体坐标、历史日期、飞机结论都留在原案例里。

用户不用学习剪辑软件。Codex 负责判断每个疑问用原文、实拍资料、机制动画还是 AI 情境画面，写代码制作、配音配乐、接入时间线、导出与核验。用户给选题、提供自己找到的材料、说出观看感受即可。工具命令是交接给后续 Codex 的，不要求用户自己执行。

## 一、先选正确的画面机制

| 观众的疑问 | 优先形式 | 做到什么才值得上动画 | 不适合的做法 |
|---|---|---|---|
| 天体在什么方向、是否在地平线上 | 真实坐标驱动的地平天穹，必要时切主观视窗 | 观众能判断方向、高度、时间变化 | AI 生成漂亮星空后把它当历史观测 |
| 两个时间是不是同一天 | 时钟拨针、实体日历翻页、原始日期截图 | 时区变换和日期差能被看见 | 把两个日期写在卡片上左右飞入 |
| 为什么一个灯变成长线/点串 | 相机快门、移动灯源、曝光积累 | 先看产生过程，再看结果和原照片 | 直接写“长曝光”却不给观众看到原因 |
| 发出信号后，为什么需要回应 | 一次往返的信号路径、应答节点 | 发出、到达、返回分别有明确状态 | 扫描圈循环、流光不停，回答已经到达仍长时间空等 |
| 黑客攻击中的请求怎样经过系统 | 与真实协议一致的请求/回应与权限状态动画 | 分清哪一步是读取、执行、认证、提权 | 红色代码雨、随意 IP 地址充当证据 |
| 钱从谁流向谁、损失怎样累积 | 交易或资产流动、账户变化、时间序列 | 每步金额、单位、方向和合计可复算 | 把走势画得更陡，或用虚构实时屏幕装作行情 |
| 多种材料指向什么解释 | 先分别看原材料，再空间汇聚 | 材料类别、可信程度和推论边界仍然清楚 | 把同源转载画成多条“独立证据” |
| 需要还原当事人的处境与气氛 | AI 情境画面、环境声、配音 | 它帮助理解处境，且身份明确 | AI 画面承担人名、金额、时间、设备型号的证明 |
| 原文究竟说了什么 | 原网页或扫描件全屏，关键词高光 | 标题、日期、署名、上下文能辨认 | 重打一段“原文”放进像官方公告的假页面 |

“科技感”不是给每一幕套蓝色网格。它来自可理解的过程、准确的尺度、克制的光和有目的的运镜。财经可以用纸质账本、交易回执、清晰的资金流；黑客可以用真实请求和受控复现；只有空间问题需要空间模型。

## 二、星月这一段为什么有效

1. **先给观察位置，后给答案。** 日期、地面参考点、方位圈先建立。观众知道“我站在哪儿”，才看得懂天体位置。
2. **同一几何系统贯穿始终。** 地平天穹、金星视线、水平投影、角尺、主观转身都来自同一组方位/高度，画面切换不是换一张没有关系的示意图。
3. **把抽象词变成动作。** “西偏北”不只是一行字：先面向报道提到的东南区域，再转身，看见另一侧的金星，最后退回完整三维模型。
4. **每次只揭示下一件事。** 金星之后才加入火星、土星；地平面变透明后，才显出地平线下的日月和其他对象；最后拨动时间检查前后变化。
5. **镜头有空间连续性。** 相邻阶段的相机起止位置连续；视差来自真实投影，不用装饰性的推拉掩盖静态内容。
6. **留白服务理解。** 暗背景、低亮度网格、金色焦点、淡蓝辅助线。最亮的是当前解释对象，字幕区不塞小字。
7. **保留范围说明。** 地面参考点不是实际机组位置；报道的“东南面”是宽方向，不伪造一个 135° 的精确目击射线；星标光晕和大小是编辑标记，不是实测亮度。
8. **解释是观众刚刚看到的动作的结论。** “来，转过去”与转身同步，金星出现后再明确说位置；不给一大段结论再补一个无关漂亮动画。

这套方法适合任何“站在哪里、朝哪里看、目标如何移动”的问题。它不适合直接解释资产负债表或黑客身份归因；那些问题要改模型，不能换标题沿用星球。

## 三、已保留的真实数据与计算

文件在 `参考库/动画/01_星月与日期/数据/`。本库保存了原始 JPL 返回、查询参数、原始正文、文档副本、绘图数据、坐标计算和历史核验记录。

**原案例参数，不是通用默认事实：**

| 项 | 原案例值 | 迁移新题时 |
|---|---|---|
| 时间 | 2010-07-07，北京时间 20:00–22:00；重点 20:40 | 根据新证据重新确定时间及不确定范围 |
| 地面参考点 | 东经 120.3°、北纬 30.2°、海拔 0.01 km | 重新查证位置，不能冒称目击者/飞机位置 |
| 方位约定 | 北 0°、东 90°、南 180°、西 270° | 在画面与计算中保持一致 |
| 高度 | AIRLESS，几何地平线上正、线下负 | 是否加入折射、地形遮挡另行论证 |
| 对象 | 金星、火星、土星、水星、木星、太阳、月亮 | 按新问题列候选，不擅自用装饰恒星作真实星场 |
| 时间采样 | 每 20 分钟一个真实节点，共 7 个 | 新题可另查询更密节点，必须实际取回并核验 |
| 画面插值 | 节点间高度线性、方位沿最短角差过渡 | 插值是动画，不是逐帧观测或精确升落时刻 |

**重要的历史状态：** 原工程曾尝试一分钟节点，但网络请求失败，结果是 `partial_do_not_use_as_full_seven_object_animation`，对象数量为 0。本库把这些失败记录放进 `数据/历史失败请求/`；它们不参与渲染。不能因为目录叫“一分钟”就对外宣称使用了一分钟真实数据。

金星坐标转换确实计算过，不是把答案写死在一个假计算界面里。输入为 JPL 提供的站心视赤经 α、赤纬 δ、当地视恒星时 LAST，加上地理纬度 φ：

```text
θ = 15 × LAST（度）
H = θ − α
E = −cos(δ) sin(H)
N = cos(φ) sin(δ) − sin(φ) cos(δ) cos(H)
U = sin(φ) sin(δ) + cos(φ) cos(δ) cos(H)
h = asin(U)
A = atan2(E,N) mod 360°
```

ENU 三维约定是 x 向东、y 向北、z 向上。方位高度进入空间点时：

```text
x = cos(h) sin(A)
y = cos(h) cos(A)
z = sin(h)
```

重点时刻复算约为 **方位 280.458860008°、高度 +10.241917991°**，与 JPL 输出列核对一致。画面只保留需要的精度。不要把六位小数当成当事人目击的精度，也不要把坐标转换称为“独立求解了天体轨道”。LAST 已经是当地恒星时，**不要再把经度加一次**。

新选题可用 `工具/动画/取回新题星历.py` 免费取回官方数据。配置必须写明时区、坐标角色、时间不确定范围和天体编号；程序保存原始响应、URL、参数、哈希。取回失败就保留失败记录并修正数据流程，不拿缺失天体当“它不在”。

## 四、源码与可运行版本怎么区分

`参考库/动画/*/历史源码/` 是原文件副本。它们可能包含旧目录结构、Windows 字体路径或当时的工程接口。原样保留是为了能追溯制作过程，**不要把这些文件直接当新工程入口**。

`工具/动画/` 是迁移后的独立引擎。它们从当前新项目根定位参考数据和本地字体，没有导入旧项目。统一入口为 `渲染范例.py`：

| 引擎 | 接口 | 作用 |
|---|---|---|
| `星月范例.py` | `frame(phase, p, captions=False)` | 原案例的三维星月与转身镜头 |
| `日期范例.py` | `frame(phase, p, captions=False)` | 原案例日期核对，真实纸页弯折与双时区拨针 |
| `曝光范例.py` | `frame(phase, p, captions=False)` | 移动灯源与积分曝光机制 |
| `雷达范例.py` | `frame(t, captions=False)` | 发射、反射/主动应答的完整往返机制 |
| `汇聚范例.py` | `frame(phase, t, duration, ...)` | 六种材料分开出现、进入真实三维同一空间、解释汇合 |

这些是**可以复现旧案例的引擎**，不是仅凭 JSON 换题的全能插件。星月字体替换为本地 Noto Sans CJK SC；保留的原片仍是原版字体。星月复现配置把数据哈希锁定，防止改了数据却遗留硬编码日期、方位、字幕解释。新主题先建立自己的数据/动作/口播设计，再复制并参数化适合的几何模块；新事实、新文字和新范围必须一起核验。

安装与复现（由 Codex 执行）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r 工具/动画/requirements.txt
.venv/bin/python 工具/动画/核验动画数据.py
.venv/bin/python 工具/动画/渲染范例.py --config 工具/动画/配置/星月_转身找金星_8秒.json
```

默认独立样品是 1280×720、25 fps、8 秒、无声音。该尺寸是验证动画本身用的；正式镜头按整片分辨率输出并逐帧检查。源码 720p 部分放大为 1080p 不等于增加了原生细节；若需要大量细小文字或 4K，要调整原生几何/字号再重渲染。

`captions=False` 去掉演示口号和“无旁白预演”字样，**保留组件本身必要的科学来源/范围说明**。合成层不再叠一份解释。日历不额外加来源条或“动画示意”；原生时区、日期、参考文本已经表达了它是什么。

## 五、星月每个阶段怎样用

| phase | 画面动作 | 旁白配合 | 最常见的错误 |
|---|---|---|---|
| `locate` | 从观察点展开地平圈和天穹 | 时间、站位先落地 | 一上来塞满七个天体名称 |
| `convert` | RA/Dec/LAST 进入，画视线和天顶投影 | 解释“把星历换成从这里看的方向” | 把公式当装饰，数值与图不同 |
| `altitude` | 视线水平投影、真实角尺 | 看见角尺后再收口“在地平线上方” | 为了好看画一个夸大的角度 |
| `azimuth` | 从北顺时针量方位 | 建立方位量法 | 把地图左右与抬头看的左右混用 |
| `turn` | 面向报道方向，转向金星，退回三维全景 | “转过去”跟转身开始同步；对象出现后给结论 | 背景不动、只让一张金星卡片滑入 |
| `compare` | 连续绕观察点，加入其他候选 | 逐个报名字时逐个进入 | 一次性出现，口播与对象对不上 |
| `below` | 地平面透明、拉开视野、显出线下对象 | 让观众先看见“下面”，再解释 | 把地平线下对象藏掉造成缺失 |
| `time` | 连续拨动时间和位置 | 扩展到时间不确定范围 | 只改时钟数字，天体不动；或者每句话从头循环 |

`p` 是 0–1 的动作进度。配音变长时，不必整段减速：可以划分连续的 `p_range` 或 `progress_knots`，在“观察结果”的稳定状态稍作停留，再接下一个阶段。不要冻结信号或天体正在运动的中途造成卡顿感。跳过阶段时要检查相机切点，不要凭接口名称认为它们必然无缝。

## 六、日期、曝光、雷达和汇聚的具体制作经验

**日期动画：** 原版不是平面数字翻牌。纸面分为 28 条带，按弯曲角、透视、正反面、投影和阴影组合，翻过的纸页留在桌面上。双时区用真实钟针运动。原案例的 EDT→北京时间相差 12 小时是因为该日期使用美国东部夏令时；新题不要全年固定套 +12。用有时区信息的日期做转换，跨日要改变日历。原始来源日期的像素固定，不把原文扭曲成假截图。翻页结束后留一眼给观众确认“哪一天”。

**曝光动画：** 两盏教学灯沿同一路径运动，一盏常亮，一盏间歇闪烁。光点扩散函数沿路径积分形成连续轨迹；有限脉冲形成有限短痕。原案例曝光设定 2.5 秒、脉冲周期 0.45 秒、宽度 0.040 秒，是教学参数，不是反推原照片的实际快门和灯频。正式镜头保留完整曝光过程，快门前先让观众把注意力放到灯上。画完后回看原照片，明确“这个机制能解释怎样的现象”，不要声称教学画面证明具体机型。

**雷达动画：** 一次雷达强调信号碰到目标再反射；二次雷达强调询问与应答机主动回答。每个机制正常播放一个完整往返，不循环补时长。已修正的二次雷达保留 6.80 秒，问答在约 6.40 秒完成，结果观察约 0.40 秒后进入下一句。这个时长是本案例的剪辑决定，不是实际电磁波传播时间。它提醒我们“需要留拍”不等于“所有动作后都加两秒”。

**空间汇聚：** 当前采用的是六路线索版，中央模型有真实空间体积、轮廓光、面明暗、视差和连续相机轨迹。线索在同一三维空间中有位置，路径沿曲线生长，随后汇合。文字保留名称、短解释和来源层次；需要阅读的原网页全屏出现后，再进入该路线，不缩成右上角画中画。网友转述、私人飞机留言、同期新闻分开呈现，不能合成一个含糊的“网上都说”。线条是推理结构，不是测量航迹；多种材料出现“飞机”解释不等于六次独立确认同一架飞机。新题如是财经调查，可以把中心模型改成真正需要解释的资金关系；不要继续旋转一架飞机。

平面四节点和动态卡片墙曾被用户明确否定，不作为默认模板。只保留当前已采用的六路空间版供参考。

## 七、声画节奏的默认规则

- 动作开始前给注意力一个落点：画面安定、口播一句引导、自然停顿，再开始演示。是否需要半拍，以台词和动作复杂度决定。
- 关键动作与词同步，结果至少让人看一眼。复杂计算可先展示问题与输入；结果出来前音乐/口播让位，结果落点再接和声收束。
- 让 BGM 延续章节气氛、用和弦/节拍过桥，不能每换镜头都硬切音乐，也不能让结论词被鼓点盖住。
- 旁白“我们来看”“转过去”“现在把这些线索放在一起”都要有对应动作。不要把完整动画放进截图角落，再靠同时播放两件事制造忙碌。
- 完整 AI 片段按已接受的原速、完整必要动作使用一次；不能为了凑台词不断循环同一动作或擅自压速。需要新增画面时先尝试台词桥、原文、合理的观察镜头。
- 每处停顿按信息量安排。曝光前需要准备，询问应答完成后只需短结果观察，章节转换需要音乐延续，结论需要一次清楚落点。它们不是同一个固定秒数。
- 组装完成后在最终 MP4 中复查，不能只看未合成的动画样品。字幕、水印、片尾、BGM 都会改变注意力分布。

## 八、字幕、来源、情境说明如何避免重复

用户明确要求：有底部来源/备注的静态截图，不再添加左上角同类备注；AI 视频和动画已有原生说明，就保留原生版本，不再叠新条。

因此每个资产都要登记 `native_labels`（文字、位置、出现时段），再决定是否补充。不要把网页本身的标题、作者、日期误判成“多余备注”擦掉；不能为了只留一处来源而删除证据内容。必要补充优先放在旁白、字幕或发布说明中，不把整屏堆成免责声明。

在星月例子里，“不是机组实测视线”是方法范围，属于原生画面；在日历里，不需要再加一条“动画展示”；在 AI 夸张情境里，已经写着“AI夸张演绎／并非历史影像”，合成时不再加第二条。

保留原片字幕安全区。不要感觉“更像电影”就擅自下移字幕；以原帧实际位置核对。字幕要让原文、高度角、日期和方位仍然可见。水印保持同镜头内不动，只在合适切点更换位置；它不能遮住原文关键词、角尺、时钟或当天日期。

## 九、新题执行顺序与检查

1. 写一个具体问题：观众看完这 5–15 秒应能回答什么。答不出来，先改表达，不急着做特效。
2. 列出输入、单位、来源、误差/不确定范围；区分观测事实、模型假设、教学参数、编辑标记。
3. 选择模型和空间约定；先做三个代表状态。前后状态讲不通，连续动画也救不了。
4. 用真实配音粗对齐动作节点，做 5–10 秒样品，连 BGM 的起伏一起看。文字与数据先完整，再做光、景深和镜头质感。
5. 计算核验与视觉核验分开：数值正确不保证看得懂；动画好看不保证事实正确。
6. 渲染、完整解码、抽查开始/中间/结束、检查原文可读和标注数量，再接主时间线。
7. 最终全片从每幕前一句开始看转场，特别检查曝光开始前、转身出现目标、日历落定、雷达回答到达、结论落点与片尾署名。

本库统一渲染器会记录配置/引擎/视频 SHA256、总帧数、完整解码帧数、尺寸、时长和实际解码联系表。另有离线数据核验脚本检查七对象七节点、金星原始行与坐标复算。静态联系表的检查只能证明抽样帧布局；对最终节奏和音乐的判断还需要连续播放。不要在记录里把抽帧检查写成“全片人工看完”。

## 十、使用与归档边界

源代码、数据、成片片段、开放字体及许可证都在新工作室内。删除或移动旧 `xsufo` 目录不会影响这里的独立渲染入口。历史查询脚本只是归档，不作为运行依赖。

第三方网页截图和 JPL 文档是原案例的研究证据。它们可以用来核对该案例与解释制作方法，不能拿去充当新题的证据。转载、再发布截图时仍然保留真实来源和必要范围。原片中涉及的观点也不被提升为所有视频的默认结论。
