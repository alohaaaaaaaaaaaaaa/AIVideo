# 导演、制片、分镜与逐镜打磨

制作水平来自每一步为观众作出的选择。复制了音色、字体或代码，只能提供起点；“能导出视频”不能作为“和原片一样好”的证明。当前审美基准是2026-10-24认可的21分59.96秒终版，不是早期18分钟拼接稿。

## 导演：先确定这段为什么值得看

每一段先写“进来时观众知道什么 → 看见什么新材料/动作 → 判断发生什么变化 → 为什么接下一段”。这不是要在画面上展示四张卡片，而是检查叙事。没有变化的重复信息可以改写、换顺序或压缩；用户要求保留的评论、支线和笑点保留其观看价值。

开场要兑现标题。原片开场的有效链条是：船票笑评让人进入 → 机场停航使反差成立 → 私人飞机评论引出待查说法 → 央视后续报道提供值得追查的依据 → “把原文翻出来”承接调查。上一轮验收样片把一句机场旁白、八秒星空和账号片尾拼在一起，虽能编码，却没有这个因果链，不应作为成片质量示范。

新题不要复刻同一台词或顺序。黑客故事可以从一次异常操作走进权限边界，商业故事可以从一笔账进入业务机制。先提出观众真会追问的问题，避免从概念课开场，或靠神秘配乐把普通事实夸大。

## 制片：把资源花在缺口上

先整理可复用的真实材料、现成画面、代码动画和声音缓存，再列缺口。镜头任务说明用途、资料来源、起止动作、预计自然时长、是否需要生成、可替代方案和采用条件。用真实资料就能表达的内容不为“高级”另造AI视频；需要明确空间或机制的内容也不把网页文字当万能画面。

生成之前用已有素材做粗剪或无付费预演，确认不是故事结构问题。用户已授权本期制作/测试时直接在范围内推进，记录调用与费用；不因模板中默认false再次询问。任务状态不明先查询，不重复付费抽卡。每个采用素材与实际文件哈希绑定；改图、改音或换版后，旧核验不会自动沿用。

## 分镜：一个镜头有一个主要观看任务

真实网页：认出来源 → 找到相关段落 → 固定阅读 → 随词强调。可以省略已经清楚的步骤。网页运动应在定位时完成；开始阅读后稳住，不持续推拉。不同层级材料分别出现，不能把媒体报道、目击、网友转述摆成等价的六票证据。

机制/空间：先建立站位或对象 → 给观察问题 → 运行一个动作 → 等到变化可见 → 解释结果。星月“转身看另一侧”的动作有明确空间含义；同样的镜头语法可迁移到数据流、权限、资金流，但天文参数不能复用到别的事实。

AI情境：环境、人物/物体、单一小动作、机位、起止状态写具体。景别为理解服务，尽量全屏原速使用；不靠裁成小窗、循环、慢放或冻结补时。已有原生情境说明只保留一份。

笑评：先让原评论可见，再读到包袱，稍留反应空间，然后通过语义回到调查。停顿并非越长越好，也不是每条固定0.8秒；要看实音声尾、动作结束和下一句作用。

## 三次打磨，各解决不同问题

1. **稿件通读**：读完整片，检查指代、承诺兑现、反证、证据层级、重复解释、结论强度和支线回收。不能只修首尾。
2. **声画粗剪**：按真实配音排镜头，检查观众是否有时间读完关键句、动画重心与口播是否同步、转场为何成立。静音看画面、只听旁白分别检查，再看组合。没有实际试听能力时，记录使用ASR/波形辅助，不能写“已听完”。
3. **最终成片逐镜检查**：必须看合成后的MP4，首中尾、动作触发前后、字幕切换和章节接缝都覆盖。检查技术之外，写下画面具体问题及修法，不能用passed列表代替目视。

新风格或新组件先出代表性短片。既定风格下的修复直接做完；用户在审片中指出的问题进入可复现对照，不能只改文案解释。

## 同画面对照怎么做

保留原片相同镜头、相同字幕时点、相同分辨率的截图。比内容位置、字形大小、行距、来源栏、红线和水印避让；不能拿不同台词帧宣称字幕一致。只有经过设计的裁切才允许改变构图。原本1920×1080全帧图像不能因为新增备注被缩成1536×864。

默认字幕是原Main样式，科学动画可显式采用原74px底距；两者是有场景依据的布局，不能全片统一加高。系统Hiragino与开放Noto是不同字形；换机器回退字体时必须做同字样帧并记录，不能说“完全一致”。颜色、描边、阴影、行宽和底距以`默认配置/视觉.json`为准。

来源备注在已设计的底部安全区覆盖或替换，不能缩整张图腾位置，也不能盖住正文。原始长网页先根据完整证据句和限定词制作阅读画面；不能直接contain全长页面让字缩到看不清。高光依靠实际截图坐标；跨行逐段划，随真实词时码触发，不按字符数均分。

## 从实际配音到镜头清单

使用`工具/导演/compile_storyboard.py`。输入绑定本次实音时间线和混音SHA，每镜通过`paragraph_id`及段内`start_offset/end_offset`定位。一个段落可以对应多镜；镜头允许先画后声或跨句，但跨段落需明确拆分，不能偷偷改变旁白长度。

工具检查镜头覆盖、整帧切点、素材哈希、视频长度、AI重复与采用记录，并生成媒体manifest和导演核对单。它不会自动判断故事好不好看。镜头表中的`viewer_task`和`transition_reason`要写具体判断，不能复制“增加趣味性”到每行。

```bash
.venv/bin/python 工具/导演/compile_storyboard.py --plan 作品/本期/05_剪辑/声画任务.json --output 作品/本期/manifest.json
```

模板只是起点，Codex负责填完；不要把技术表格交回用户。实音或素材更换后，绑定不匹配就重新核对该处与后续剪点。导演决定先落实，再让自动化确保它没有在合成时丢失。

## 每次交付要说清的三个层次

- **原版一致项**：实测保留了哪些参数、构图、音符/音轨、动作、原文和时码。
- **有意变化项**：为什么变、改了哪一处，以及可直接播放的对照。
- **仍待判断项**：只做了技术检查、抽帧或模拟接口的部分，实际新生成是否验过，新故事是否经过完整审稿。

“全都完美”“任何题材自动同水平”不是可验证的验收结果。目标是保住已认可标准，发现具体差异就修复，并让每期完成同等深度的导演与成片审查。

## 修改留拍后，动画也必须同步

`assemble`同时输出绑定`timeline_sha256`和`narration_sha256`的`visual_cues.json`。分镜若使用其中动作，填写顶层`visual_cues`与`narration`路径；镜头填写`cue_ids`及`cue_render_receipt`。动画重渲染后回执包含当前`asset_sha256`、`visual_cues_sha256`和实际采用的`cue_ids`。工具拒绝旧旁白、旧时间线、落在镜头外的触发点，以及未重渲染的旧动画。

回执是制作记录，不能仅修改哈希来让旧动画“通过”。渲染器必须真正使用当前触发时码；Codex还要在最终视频中检查动效开始/完成与台词的关系。已采用原片的固定参考镜头可以明确保留原时码，不应伪装为新生成的cue绑定案例。

本轮用实际开场分镜测试了正确输入，以及换实音、换素材、剪点留洞、视频长度不足、缺AI采用记录、旧动画回执等失配情况，结果在`检查/本轮对标/导演分镜绑定核验.json`。对应测试不代替目视判断。
