# 默认声音：南方小哥 ×《一起查案》

这套声音已经从萧山项目中拆成独立工具，音源本体、许可、音符编排、混音算法和真正成片选段均在本项目中。换做黑客事件、商业调查、金融骗局或历史事件，默认仍采用同一位南方小哥、同一语速与同一套柔和钢琴／弦乐／拨弦／颤音琴。**只有用户主动要求更换时才换音色或整体配乐风格。** Codex 可以按新台词重新写音符、换和声密度、安排呼吸与落拍；不要把旧音乐录音整条循环到新片。

用户认可的是整套听感：自然男声讲调查，音乐有好奇心和推进感，认真时克制，评论时稍轻，结论说完才落定。不能因新题材叫“黑客”就自行换成重电子鼓，也不能因叫“财经”就换成新闻播报腔。

## 2. 配音身份和生成方式必须固定

| 项目 | 采用值 |
|---|---|
| 服务／模型 | MiniMax `speech-2.8-hd` |
| 音色 ID | `Chinese (Mandarin)_Southern_Young_Man` |
| speed / vol / pitch | `0.96 / 1 / 0` |
| emotion / language_boost | `neutral / Chinese` |
| 原始输出 | 44.1kHz、单声道、MP3、256kbps |
| 剪辑工作格式 | 解码至48kHz、单声道、float32 WAV |
| 字幕接口 | 提供方真实词时间戳，保留原回执 |

“neutral”不代表平铺直叙。用一句话的长短、标点、语义分句、适量短暂停顿形成自然表达。先生成一小段，听重点名词和ID，再批量。不要靠整体加速把长稿塞入画面时长；旁白的自然长度先确定，再调整镜头和动作时框。

配音分段按完整语义组织，不要逐字生成、不把每个字幕条都单独合成。建议一段一个完整意思，约1–4句；段太长会不利于局部修音。保存原始MP3、提供方时码、处理后WAV、正式文本与实际TTS文本、每次回执及哈希。

### “啊子牙”和特殊读音的真实经验

画面、正式文案、字幕始终写 **“啊子牙”**。音频把它当作一个名字连读：`ā zǐ yá`，不读成“啊，子牙”。已采用的方法是仅在TTS输入写“阿子牙”，并加入 `{"tone":["阿子牙/(a1)(zi3)(ya2)"]}`；姓名所在整句／整段重配。不能分别剪出“啊”“子”“牙”拼起来。

本项目 `tts.py plan` 会对该姓名应用已验证规则，同时保存原文。原片重配那段自然长度3.63394秒，放入原有4.68秒时框，尾部留1.04606秒；没有压缩音频。此数值仅供参考，新句子必须量实际长度。

网友ID `p.o.l.i.c.e` 的旁白读完整英语单词 `police`，引文画面仍可保留原拼写。新闻中的日期、机型、金额、英文缩写、人名需单独核读；不要把ASR识别的同音字差异自动当成配音错误。新财经选题应在`tts_text`显式写金额／百分比的预期中文读法，例如正式`123.45万元`对应实际配音`一百二十三点四五万元`；原`text`仍保留数字。不能把旧航空编号逐位读法自动套到金额，年份／编号／金额语境由读音计划明确。

## 3. TTS离线计划、缓存、预算与付费执行

凭据只通过环境变量 `MINIMAX_API_KEY` 提供。工具不读取旧项目的 `ky.json`，不会把密钥写入计划、回执或日志。用户私有凭据由工作室统一入口管理。

输入格式见 `参考库/声音/TTS输入示例.json`：

```json
{"paragraphs":[{
  "id":"C01_P001",
  "text":"我是啊子牙。今天我们查另一件事。",
  "phrases":["我是啊子牙。","今天我们查另一件事。"],
  "tts_phrases":["我是啊子牙。","今天我们查另一件事。"]
}]}
```

`phrases`连接后必须与正式`text`完全相同。若使用`tts_text`，`tts_phrases`连接后必须与它完全相同。正式字幕与读音适配文本分开保存。

在项目根目录执行，以下 `python` 指工作室自己的虚拟环境：

```bash
python 工具/声音/tts.py plan --input 参考库/声音/TTS输入示例.json --output 临时预览/声音计划.json
```

该命令只生成计划，**绝不调用服务**。2026-10-26核对MiniMax官方定价，`speech-2.8-hd`为3.50元／万输入字符，汉字计2个字符，英文字母、标点等各计1个；扩展汉字也按双权重计。证据在`参考库/声音/价格核验/`。这是有日期的参考，不代表未来永久同价或账户实际扣款；本期执行必须用本期核价证据及预算。必要时以`--rate-cny-per-10k`更新计划。

```bash
python 工具/studio.py tts execute --plan 临时预览/声音计划.json --output 临时预览/声音缓存 --authorization 本期授权记录.json --budget-cny 预算上限
```

`预算上限`是本次已授权预算的数字，此处故意不预填一个默认金额。执行遵循现有用户授权及工作室预算规则，不因模板而重复索要已经给过的授权。

- 每个请求按模型、文本、音色、参数、读音词典计算SHA256。成功且音频哈希相符就复用缓存，不再付费。
- 请求前先写`submitted_awaiting_response`，请求后写明成功、明确拒绝或状态不明；生成失败不能偷偷重复扣费。
- 超时、断网、成功但未收到完整音频：停止，查回执／账单／trace id；不能假定“没返回＝没生成”。
- 仅确认是服务商1002限流且没有音频时，允许人工检查后使用`--retry-confirmed-rejections`再提交；旧回执归档，预算保守计入历史尝试。**没有自动网络重试**。
- 若只有字幕下载失败，恢复那份字幕即可，不能为补字幕重新生成整段声音。
- 连续请求间隔7秒，串行提交，减少限流和重复计费风险。
- `--only C01_P001`可只修指定段。音色模型或服务接口如果不可用了应报告具体错误，不能自行换成另一个声音。

新付费请求还必须绑定`TTS授权记录示例.json`所示记录：真实已有用户授权、计划SHA、允许的段ID、请求次数上限、预算、当前型号费率、核价时间与证据SHA。7日以前的价格记录需刷新；计划、价格或型号改变就拒绝执行。此记录由Codex依据真实对话填写，**不是要求用户重新学表格，也不是让已授权用户反复批准**。成功缓存复用不要求新授权、不再次请求。测试授权`mock_only`禁止真实联网。离线状态机回归在`TTS离线执行核验.json`；本轮真实接口仅一次成功，无重发。

## 4. 电平、真实时码与局部修音

```bash
python 工具/声音/prepare_voice.py --plan 临时预览/声音计划.json --cache 临时预览/声音缓存 --output 临时预览/处理后旁白
```

这一步不调用TTS。解码至48kHz，使用真实词时间戳，把正式短句映射到实音；不按字符比例编造字幕时间。实际词跨过字幕短句边界时会合并相邻字幕，避免把一个词硬切两半。遇到无法匹配的句子停止该段，保留差异供核查。

采用原片有声250ms窗口的中位RMS作为电平参考：0.159369774，约−15.9519dBFS。匹配电平后，对过高峰值使用原片同样的20ms前视、50ms保护、10ms平滑，峰值上限0.82。这个电平匹配在旁白准备阶段进行，混音阶段不再随意压低或“美化”人声。

输出：每段WAV、JSON、SRT及`paragraphs.json`。JSON保留自然时长、样本数、电平变化、读音文本与正式文本、独立ASR尚未运行的状态。提供方时间戳负责对齐，独立不带提示词ASR／重点试听用于核读，两者不能互相冒充。

局部修音优先重配一整句或一整段。同一模型和参数，匹配同一电平；若自然长度放得进原时框，可只补末尾静音，保留其余全片。若放不进，就延长真实时框并重算后续字幕、画面、音乐、章节、水印和导出时码，不能强行拉伸声音。先保存被替换段及其SHA。

## 4.1 段落到全片：单一真实采样账本

`prepare_voice.py` 输出各段48kHz单声道WAV及段内词时码；它们不能直接当全片混音，也不能把每段SRT当全片字幕。使用 `assemble_voice.py` 统一编排：

```bash
python 工具/声音/assemble_voice.py --paragraphs 作品/本期/声音/处理后旁白/paragraphs.json --layout 作品/本期/声音/layout.json --output 作品/本期/声音/编排_v001
```

`paragraphs.json` 中 `audio` 相对该清单文件解析。布局Schema见 `工具/声音/assembly.schema.json`：

```json
{
  "fps":25,
  "segments":[
    {"id":"C01_P001","chapter":"01","chapter_title":"开场","music_mood":"comments","tail_seconds":0.4},
    {"id":"C02_P001","chapter":"02","chapter_title":"开始调查","music_mood":"trace","tail_seconds":0}
  ],
  "music_cues":[],
  "sound_cues":[]
}
```

每秒48000样本，25fps每帧1920样本。工具保留一段的全部实音采样，在末尾先补不足一帧的0–1919个静音采样，随后才加布局中明确填写的`tail_seconds`；不会裁掉最后辅音，也不会统一增加额外观察拍。显式tail须为整帧，默认0。段ID不得漏用或重复，章节按连续顺序组织，ID用01／02等数字。

输出 `narration_48k_mono.wav`、`timeline.json`、全片`subtitles.json/.srt`、`media_chapters.json`、每章WAV和 `assembly_verification.json`。时间线保存 `sample_start/speech_end_sample/sample_end`、`frame_start/frame_end`、自然时长、帧补齐与编辑尾拍两种数量。每个短语加的是该段真实采样起点，段内时距保持。按同一章及音乐情绪合并 `music_sections`，可直接送入 `score_mix.py --timeline ... --narration ...`。编曲输出的`mix_48k_stereo.wav`直接填写媒体manifest的`audio.path`；`subtitles.json`和`media_chapters.json`分别进入manifest字幕与章节。画面shots总帧数必须等于时间线frames。

音乐／音效／画面事件可带`segment_id`，表示其时间是该段**原始输入WAV**内的实音秒数；编排器根据样本账本转换到全局秒。只要插入段内停顿，全部事件必须使用这种锚定，拒绝沿用未绑定的旧全局秒。不得在章间音乐桥再次重复加已经记入tail的秒数。

联动样品在 `参考库/声音/整段联动样品/`：两段实际旁白，分别282240、174429样本。只补291样本对齐帧，加布局明确的1.6秒尾拍，总长11.12秒／278帧。完整采样对照确认零裁字、零变速，字幕和章节来自同一账本。这是工程衔接测试，内容拼接不代表新视频的叙事方案。

局部修音时 `prepare_voice.py --only ID` 会更新该段并保留 `paragraphs.json` 中其他采用段，避免只修一句把全片清单覆盖掉。编排输出须使用新目录，核验后再更换采用版本。

## 5. 默认配乐究竟如何制作

不是从音乐库找一首背景歌，也不是让音乐API生成固定长度歌曲。工具对新片的实际章节时长**逐个写音符**，使用本地GeneralUser GS采样音源生成四个乐器分轨，再根据本片旁白避让。

| 乐器 | 零起始GM program | 比例 | 音色处理与用途 |
|---|---:|---:|---|
| 钢琴 | 0 | 0.90 | 4200Hz低通，稀疏两三音问句，调查的熟悉感 |
| 弦乐 | 48 | 0.31 | 2400Hz低通，慢起音与短房间尾音，托情绪 |
| 拨弦 | 45 | 0.55 | 3600Hz低通，轻微推进，不做满屏节拍器 |
| 颤音琴 | 11 | 0.20 | 4600Hz低通，极少点色，不当“证据成立”提示音 |

各乐器先110Hz高通；轻房间混响约1.1秒，弦乐约1.4秒。钢琴湿声比例0.23，其他0.13。用原片`音源校准.json`的raw RMS标定保持音色比例，不能换个SF2后继续假定音量一样。音乐另削弱1.3–3.7kHz，给说话的清晰度腾位置。

调性围绕A小调与延伸／挂留和弦发展：Am9、Fmaj9、Dm9、Cmaj7、Em7、Esus、G6、C6。结论说完才落温和C大调终止式。每四小节有一段变稀，避免22分钟持续拨弦让人疲劳。没有惊吓尖音、夸张悬疑鼓点或长时间低频嗡鸣。

| music_mood | BPM | 使用场景 |
|---|---:|---|
| `discovery` | 84 | 查到新的可核对材料 |
| `trace` | 90 | 原文查证、时间线、逐条追索 |
| `mismatch` | 80 | 日期／说法对不上，先冷静检查 |
| `early` | 86 | 背景与早期记录 |
| `comments` | 88 | 真实网友评论，保留一点趣味 |
| `window` | 76 | 机制解释、观察、较谨慎的分析 |
| `recap` | 86 | 汇聚线索，逐条归纳 |
| `judgment` | 82 | 结论之前，减脉冲让台词主导 |
| `resolved` | 82 | 判断已由证据讲完后的完成感 |
| `coda` | 90 | 彩蛋、评论收尾 |
| `outro` | 86 | 自我介绍和下一期问题 |

这些是音乐语义，不限定题材。黑客追踪日志可以用trace；财经核对账表同样可以用trace。证据不足时不能靠“胜利音乐”把推测包装成定论。

## 6. 编曲／混音的可调用接口

入口：`工具/声音/score_mix.py`；格式约束：`工具/声音/timeline.schema.json`。时间全部是本次渲染的本地秒，和全片绝对秒不要混用。`music_sections`按顺序无缝覆盖整段；实际旁白WAV必须与duration同长（允许2样本舍入差）。

```json
{
  "duration":18.76,
  "music_sections":[
    {"id":"S01","start":0,"end":5.88,"music_mood":"comments"},
    {"id":"S02","start":5.88,"end":18.76,"music_mood":"discovery"}
  ],
  "music_cues":[
    {"type":"space","start":5.6,"end":6.35,"gain":0.708,"reason":"转入新线索，给口吻让半拍"}
  ],
  "sound_cues":[]
}
```

```bash
python 工具/声音/score_mix.py --timeline 参考库/声音/离线复现样品/timeline.json --narration 参考库/声音/离线复现样品/voice_48k_mono.wav --output 临时预览/声音复现
```

- `--plan-only`只写逐音符JSON和可编辑MIDI，不渲染音频。
- `--music-only`渲染四乐器与轻音效，不需要旁白混音。
- `--reuse-music`仅在时间线哈希相同且已有编曲记录时复用；旁白改动仍重新检测避让。
- 输出`score.mid`使用标准MIDI type1，固定120BPM换算秒数以保持精确起音；实际每段原BPM与和弦保存在JSON，不会丢失。
- 输出`music_score_48k_stereo.wav`是未按旁白避让的谱面音乐；`music_48k_stereo.wav`才是实际入片的音乐。不可混用。
- 最终混音是`mix_48k_stereo.wav`；同时保存`voice_48k_stereo.wav`、`sfx_48k_stereo.wav`、四个`分轨_*_48k_float.wav`、试听MP3、编曲记录与混音核验。
- 每次正式修订使用新目录，核验后再把工作室采用版本指向它。

默认没有音效。仅在画面上确有翻页／检索动作时提供`page`／`search`时码；`cabin`／`airport`是程序生成的情境氛围，只适用于明确的示意画面，不能伪装成真实历史录音。

## 7. 为什么音乐与南方小哥能贴合

1. 单声道旁白用等功率居中：左右声道各除以√2，合计能量保持。混音不会为了音乐去压低已认可的旁白，也不会变速。
2. 音乐先105Hz高通、1800Hz附近宽Q0.65削4.5dB、7000Hz低通。人声主要信息区域不被钢琴弦乐顶住。
3. 用真实旁白每10ms测RMS；阈值约−43dBFS。前视60ms，把字间短缝连起来；35ms压低，480ms释放。有声时音乐最低到原来的0.25，约−12dB；句间平滑回来，不一字一抽。
4. 以250ms有效说话窗衡量实际声乐比，中位目标音乐比旁白低21dB；弱字局部保护上限约低14dB。1–3kHz信息带另有低9dB的保护，不只看全频平均数。
5. 非人声混合峰值不足时仅降BGM／音效；旁白自己峰值不合格应返回旁白处理阶段。混音样本峰值保留0.94余量，成片再检查AAC真峰值。
6. 逐段重编并不意味着每个章节换一种风格。沿用熟悉的两三音问句和音源，和声、密度与真实剧情一起变化。

`混音核验.json`报告测得的实际比例；中位最终可能比−21dB更低，因为弱字保护继续削减，这是正常的。不要为了恰好等于−21而取消保护。

## 8. 幕间承接、观察留拍和结论落拍

**幕间：** `bridge.py`沿用上一章最后和弦、下一章第一个和弦的共同音，现场生成短弦乐桥；较长间隙可有一次轻钢琴回应。过桥前后重叠0.5–1秒，用余弦权重交叉，权重总和为1。只动音乐，不淡出原旁白，不拿旧音频波形循环。音乐桥受邻近音乐峰值及人声保护限制，不突然变响。

输入总时间线的chapters含`id/start/end/narration`，ID用01、02等；`narration`相对该JSON文件解析。每章BGM目录是`C01/`、`C02/`，放该章`编曲执行计划.json`与`music_48k_stereo.wav`、`sfx_48k_stereo.wav`。所有接缝逐一填写，已经把停顿算进章尾时 `duration`必须为0，防止重复加时。

```bash
python 工具/声音/bridge.py --timeline 参考库/声音/离线复现样品/bridge_timeline.json --transitions 参考库/声音/离线复现样品/bridge_transitions.json --bgm-root 参考库/声音/离线复现样品/桥接输入 --output 临时预览/音乐桥复现
```

**观察留拍：** 先让观众知道“看什么”，动作开始前留一口气，动作进行时允许BGM承接，动作完成就及时接解释。不能只给每幕尾部一律加两秒，也不能把动画完成后的静止帧拖很久。旧片的相机曝光需要看清常亮拖线、闪灯成点；二次雷达完成问答后再空等9.52秒却像卡顿，最终删掉了那段静音。两种情况不能机械套同样时长。

正式编排优先使用`assemble_voice.py`的段落`pauses`：每项含`at`、`duration`、`source_audio_sha256`、`reason`。切点前后5ms峰值必须低于0.0001，不能跨未拆分字幕句；时长必须整帧且不超过3秒。它逐块保留所有原采样，同一次编排自动移动字幕、音乐、音效、结论和`visual_cues`；`visual_cues.json`绑定新时间线及旁白SHA。画面必须据此重建，不能把旧镜头表拼上新音频。插入停顿时未提供画面锚点就拒绝编排。单独`pause.py`仍可作诊断，但只输出移位表，不是完整成片流水线。

**结论：** 先让观众听清“我的结论是”，可按实际口吻留约半拍；正式判断时音乐降约2.5dB。必须定位最终关键词的真实字尾，**字尾后0.10秒**才放`resolve`，不要在“我的结论是”就抢先胜利。终止式为5个钢琴音＋4个弦乐音，并去掉普通章尾额外终止式，避免双重落拍。后面至少留2秒音乐尾音，旧片采用2.88秒。此时画面结论文字、重音、音乐和弦要对在同一语义节点上。

正式`resolve`不再手填一条孤立秒数。布局写`conclusion_cue`，绑定段ID及原WAV SHA，给出`core_start`、`core_end`、`scope_end`、`post_word_delay:0.10`和真实核验方式；编排后绑定总旁白SHA。`editorial.py`检查真实5ms波形窗口，防止字幕过早结束就抢先落拍，再自动生成降乐与终止式。`scope_end`只收束结论段，之后作者片尾继续保留编曲。即使`--plan-only`或`--music-only`，带结论也必须传真实旁白。声学能量尾部不等于语义字尾，必须结合上下文；ASR同音字也不能自动改正式文案。

整片使用`score_film.py --timeline 本期timeline.json --narration 本期48k旁白.wav --output 新混音目录`：逐章作曲、逐章避让，然后实际执行所有音乐桥。时间线必须有`chapter_music_strategy`，模式`explicit_bridges`，每个接缝列`after_chapter`、`duration:0`和0.5–1秒前后重叠；停顿已存在于样本账本，桥接不再加时。完全无旁白的动画章节可显式指定`silent_music_rms_dbfs`（−50至−20dBFS），由前后实际音乐电平选择；不能凭空声称它通过了人声相对电平检查。

实音回归`节拍联动回归/`使用完整结论和作者片尾，额外0.4秒仅用于测试，不替换已认可剪辑：字幕、图像揭示、音效和字尾同时移位，结论9.965秒落拍，后续片尾音符保留，真正桥接后17.60秒，−17.06LUFS/−4.90dBTP，原旁白采样完全保留。`结论落拍对标/`另保留同一完整12.36秒原版/重编对照：新短片从小节开头重编，不能等同原188.96秒章节末端的和声阶段；实际声学尾9.465秒比旧记录9.38秒晚85ms，所以新落拍9.565秒比原9.48秒也晚85ms。差异已记录，没有拿相近响度冒充节奏完全相同。

原开场可用`rebuild_opening_reference.py --output 新目录`独立复现：带入已保存原旁白、原C01逐音符计划以及C02前4秒原章节分轨作为音乐桥标定上下文；无需旧项目、无需新付费、没有循环旧BGM录音。

## 9. 交付前声音检查

- 正式文本与配音逐段相符，姓名、数字、缩写、引文和英语单词重点检查。
- 字幕用实际词时码，避免“人已说完、字幕还没来”。重复修音后更新同一段字幕，不保留旧字幕位置。
- 逐章试听开头、接缝、笑点、机制动画、最终结论、作者ID。技术检查通过不代表主观节奏一定合适。
- 音频长度、帧数、章节和视频时长一致；旁白不变速，不缺字；所有保留音频的哈希或采样对照通过。
- 完整解码，样本削波为0；AAC输出再测真峰值，建议低于−1dBTP。整体响度以−18.5至−15.5LUFS为参照，弱字优先。
- B站水印版和无水印版应使用同一条最终混音，不重复随机生成配音或音乐。
- 保留分轨和编曲计划；未来只改水印、截图或字幕位置时，不重新动已认可的声音。

来源：https://schristiancollins.com/generaluser.php ，仓库：https://github.com/mrbumpy409/GeneralUser-GS 。原始下载URL、字节数、SHA保存在音源目录。不要单独删掉许可证或用不明来源音色替换。
