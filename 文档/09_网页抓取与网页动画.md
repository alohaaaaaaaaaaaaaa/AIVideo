# 原网页抓取、原文高光与查阅动画

这份流程保留萧山成片里真正采用的两段动作：央视报道的“查找、滚动、停在原句”，以及舟山军事新闻的“鼠标移向标题、点击、进入正文”。原 HTML、原站 CSS、原始截图、构图截图、坐标、动作参数、旧制作源码、最终成片片段和新工作室独立重渲染都已保存。它们是以后制作新闻、财经公告、黑客事件公告、论坛评论时的视觉参考；旧新闻事实不能直接套到新选题。

直接打开 [网页参考播放器](../参考库/网页取证/看网页参考.html)。两个“原片采用段”含原旁白与 BGM；两个“独立重渲染”是可复用的无声画面素材，交给主时间线配音配乐。另有平湖原页从 HTML 抓取到实音划线的完整新跑通示例。

## 2. 原网站、保存原页与后期动作的区别

央视原资料 URL 为 `http://news.sina.com.cn/c/sd/2010-11-19/065721497404.shtml`，网页标题为《央视〈经济半小时〉：低空开放可淘金？》。页面是新浪转载的节目实录。网页署期为 2010-11-19 06:57，正文注明节目于 11 月 18 日播出；两者不能混写成同一天。

舟山原资料登记 URL 为 `https://news.sina.com.cn/c/2010-06-29/051717723846s.shtml`，标题《解放军发禁航通告 将在东海实弹射击》，署期 2010-06-29 05:17，稿源“四川新闻网—成都商报”。正文完整保留 6 月 30 日至 7 月 5 日、每天零时至 18 时、五点连线海域、禁止各类船舶进入等限定。这篇报道不能当成 7 月 7 日机场空域关闭的通告。

保存的 `.html` 是已有原资料字节。新工作室本轮重新渲染它们，**没有把旁白重打一遍冒充新闻原文，也没有新造官方网页**。`rendered_dom.html` 是浏览器运行后的 DOM 序列化，和“原始资源/main_original.html”承担不同职责；引用追溯优先看保存原始字节、来源 URL 和原页截图。

央视画面的“页内查找”小框、逐字输入、滚动曲线、最后聚焦，以及舟山画面的鼠标箭头、点击圆圈，均为后期查阅动作。底图来自真实保存原页。它们不是 2010 年的现场屏幕录像，也不是被伪造出来的网站原生控件或真实搜索结果。制作记录必须明确这一区别；不要在成片里堆叠工具说明破坏阅读。

原页有少量失效图片、广告或未保存资源。离线抓取只加载明确保存的 HTML/CSS；其余请求全部阻断并记入 `requests`。不得用生成图片补造缺失新闻正文或标识后再声称是完整原站截图。

## 3. 在新电脑准备浏览器

从工作室根目录运行；已有 `.venv` 时直接复用。浏览器渲染不调用付费生成 API。

```bash
.venv/bin/python -m pip install -r 工具/网页/requirements.txt
.venv/bin/python -m playwright install chromium
```

抓取工具优先使用当前 Playwright 安装对应的 Chromium；缺失时发现已有 Playwright 浏览器缓存，也支持明确指定 `--browser /实际路径/Chromium可执行文件`。它没有写死本机用户名或某个缓存版本。首次安装浏览器需要下载；若网络不通，应说明浏览器尚未安装，不能把失败截图冒充成功。新机运行仍需要 Pillow、NumPy、imageio-ffmpeg 等渲染依赖，均列在工作室依赖及 `工具/网页/requirements.txt` 中。

## 4. 获取原页并保留准确上下文

先建立选题自己的 `资料/网页/来源ID/`，写入来源登记：媒体/作者、原 URL、标题、原文发表时间、获取时间、原始材料还是转载、精确引文、它能证明与不能证明什么。来源日期和本次获取日期分开。一个保存文件的修改时间不自动证明历史创作时间。

两种抓取模式：

1. `public_url`：从公开页面读取，不加载登录状态，仅放行 GET/HEAD，保留返回的 HTML、CSS、图片/字体资源及响应信息。出现鉴权、访问拒绝、验证码或限流就记录失败，不绕过。
2. `archived_html`：使用 `html` 指向已经保存的原 HTML；将其 URL 和明确保存的 CSS 资源原字节交给浏览器；其他请求全部阻断。正文、CSS 不注入改写。适合旧站归档和可重复制作。

抓取配置中的 `regions[].quote` 写完整段落。`marks[].quote` 才是准备划线的小句。保持作者、日期或上下句在相邻阅读镜头/原图中可追溯，不为了支持结论裁掉限定句。新配置先复制 `平湖原页/输入/抓取配置.json`，替换为新题真实来源，不能只换标题。

```bash
.venv/bin/python 工具/网页/capture_evidence.py \
  参考库/网页取证/平湖原页/输入/抓取配置.json \
  --output /tmp/平湖原页_本次重抓
```

输出必须是新目录，工具不会覆盖已有证据。现有三个已跑通的输出在 `平湖原页/抓取_20261026/`、`央视原页滚动/原页重抓_20261026/`、`舟山报道点击/原页重抓_20261026_v3/`。

舟山本轮第一次、第二次捕获曾失败：HTTPS 离线 origin 下，原 HTML 的 HTTP CSS 被浏览器混合内容规则拦截，正文铺满 1440 像素宽，固定 720 像素裁区会切断全文。工具正确拒绝了该裁切。修复采用明确的 `archive_render_url`：保存原来源 URL 仍为 HTTPS，仅在完全离线回放中使用原 HTTP origin 加载原 HTTP CSS；没有修改 HTML，也没有向公网发送请求。区别写入 manifest，失败目录保留在该范例的 `失败记录/`。以后遇到类似问题，应先检查请求日志和样式，不凭空缩字、改写网页或删除引文来通过检查。

## 5. DOM 原文坐标如何成为画面红线

抓取工具使用 `TreeWalker` 收集页面文本，再用 `Range` 定位原引文。引用横跨 `<span>`、`<b>` 等节点仍能连续匹配；选择必须唯一。存在同文多处时，先缩小真实 `selector`，或经上下文核实后给显式 `occurrence`，不能默默取第一个。

每段保留全文、上下文、CSS 文档坐标、截图裁区和 DPR。对于 CSS 文档矩形 `[x1,y1,x2,y2]`，截图像素为：

```text
px1 = (x1 - clip.x) * DPR
py1 = (y1 - clip.y) * DPR
px2 = (x2 - clip.x) * DPR
py2 = (y2 - clip.y) * DPR
```

构图再次缩放时，所有矩形乘同一个比例。平湖示例用 720 × 326.25 CSS 裁区、DPR 3，在 1920 × 870 的正文区域展示，底部 210 像素只留一处来源与字幕安全区。截屏尺寸可能有不到 1 个像素的取整差，审计会检查而非强行变形正文。

高光保持原段清楚，外围原页作 GaussianBlur 8.5 与深色 0.36 混合。没有把正文换成卡片，没有重排字，没有默认黄色整段荧光笔。红线默认宽 5 像素，颜色沿用原片，通常 0.52 秒写完；跨行短句沿真实行序连续画完，不能一条直线跨过空白。

`audit_capture.py` 检查截图/资源 SHA、引文仍处于完整上下文、所有坐标变换与截图边界。几何通过不等于画面已检查；实际看过原图与编码帧后才能填写 `--visual-note`。

```bash
.venv/bin/python 工具/网页/audit_capture.py \
  /tmp/平湖原页_本次重抓/capture.json \
  --output /tmp/平湖原页_坐标核验.json
```

## 7. 央视滚动动画的实际工序

原准备脚本 `原制作记录/准备查阅原页.py` 对原 HTML + 原站 CSS 做 DPR 3 截图，保存 CSS `[x=200,y=0,width=720,height=850]` 的连续条。所用原始条、截屏参数、DOM 坐标都在 `输入/`。新独立渲染直接读这条连续原页像素，避免每一帧重新启动浏览器。

2.80 秒镜头的节奏：

- 0–0.8 秒保持标题位置；0.3 / 0.6 秒先后出现“萧”“山”。文字输入框是编辑层。
- 0.8–2.35 秒，视窗从 CSS y=10 滚到 y=346，视窗 720 × 405，曲线 `p²(3-2p)`，起止减速。
- 2.4–2.8 秒与原涉案段聚焦构图做 0.4 秒融合；2.55 秒移除查找框，进入稳定阅读。
- 落点的“杭州萧山机场”采用原镜头保存的暖色短线；这只是原查找动作的选择态，不改变全片阅读红线的默认颜色。
- 接下来读整段时固定画面，按“日期→机场→经有关部门证实→小型私人飞机→典型黑飞”的真实旁白锚点推进，不一边读一边持续漂移。

```bash
.venv/bin/python 工具/网页/animate_evidence.py \
  参考库/网页取证/央视原页滚动/制作配置.json \
  --output /tmp/央视原页滚动_独立重渲染.mp4
```

换新题时修改真实连续截图、落点截图、起止视窗、查找词、词坐标、时长和来源底栏。查找结果必须在同一原页真的存在。跨网页切换应另做真实页面切镜，不假装成同一页面的连续滚动。

## 8. 舟山点击动画的实际工序

原页面捕获源码是 `原制作记录/捕获走访与军事报道.py`，动作源码是 `原制作记录/合成本环.py` 的 `cursor()` 与 `local_action(open_M01)`。采用缓存为 `原采用缓存_S09.mp4`。新入口不需要运行旧项目任何代码。

输入 `标题日期高光.png` 已保留原新闻标题、日期、稿源，以及画面底栏。不要再加第二处来源。4.36 秒内，鼠标从 `(1710,760)` 移到 `(1140,365)`：前 65% 时长作 smoothstep 移动，然后停住；点击脉冲中心在镜头 78% 处，约 3.40 秒，脉冲半宽为时长的 13%，圆圈半径从 8 至 32 像素。画面底图不推拉、不重排。

点击只是“把注意力带到这篇真实报道”的编辑动作。原片不是展示一个真实链接请求成功的录屏，也没有伪造搜索列表。下一镜切原文完整通告，先看清训练日期和海域，再听分析；BGM 可以跨这个切镜延续，但不要额外制造漫长空白。

```bash
.venv/bin/python 工具/网页/animate_evidence.py \
  参考库/网页取证/舟山报道点击/制作配置.json \
  --output /tmp/舟山报道点击_独立重渲染.mp4
```

换新题时读取新网页标题实际区域，再确定鼠标终点。不能让箭头点击不相关日期或空白，更不能让此动作暗示没有实际发生的系统操作。黑客事件的操作演示尤其应标清是示意还是实际测试记录。

## 9. 缓存、合成与验收

抓取按版本留目录，原 HTML 和原截图不覆盖。动作渲染缓存签名包括配置、渲染器、截图和捕获记录的 SHA。输入相同且输出哈希符合时复用；有变化则要求新版本输出，不让旧视频悄悄混入新时间线。新抓取改变浏览器/字体后必须重算坐标，不直接照抄旧坐标。

`animate_evidence.py` 输出无声 H.264/yuv420p、1920×1080、25fps，不引入 1088 像素自动补边。它不烧旁白字幕、不添加用户水印。已完成的来源底栏作为画面的一部分，交给主媒体合成时走全幅，不因 `source_note` 再把画面缩小。字幕、BGM、旁白继续由工作室媒体入口统一处理。

每个关键镜头实际解码检查：首帧、红线开始前/途中/结束、滚动中、落点、切到下一镜。确认没有上下文截断、跨行错位、假字幕、重复备注或额外画中画。原成片参考与独立渲染使用相同原始内容，但新浏览器截图或字体回退不保证像素完全一致；回退必须披露。

本轮 `全解码核验.json` 对 10 条视频逐帧解码；`编码实帧联系表.jpg` 提供 16 个从实际编码视频解出的关键帧。三个正式捕获的坐标检查分别通过 41、54、50 项。`检查/网页取证失败模式_20261026/失败模式核验.json` 实际验证了 9 项行为：跨节点匹配、原文与标记精确、重复引文拒绝、缺失引文拒绝、裁断拒绝、公开 GET、原 HTML 保存、403 停止和字节损坏拒绝。公开模式测试只使用本机回环 HTTP 夹具，没有声称本轮重新访问了新闻网站。

实际观看记录与当前材料边界见 [本轮核验说明](../参考库/网页取证/本轮核验说明.md)。以后由 Codex 完成这些动作，用户只需要审选题、审稿和看样片；不要求用户学剪辑软件。
