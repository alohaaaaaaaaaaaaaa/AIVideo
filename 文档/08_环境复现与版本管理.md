# 环境、路径与断点接续

## 私有 Git 保存

工作室可保存到用户的私有 Git 仓库。2026-10-26上传准备核验见`检查/Git上传准备.json`：正式候选文件约1.11GB，无超过50MiB的单文件；检查了项目外现有凭据值是否混入候选文本及常见令牌模式，未发现匹配。该扫描不等于穷尽所有秘密类型。尚未指定远端，也未执行上传。

`.gitignore`排除本地环境、临时缓存、渲染历史、日志、压缩备份和凭据；保留当前采用样片、音源、字体及许可、网页原件和源码。不要一律忽略MP4/WAV或所有英文`cache`目录，否则会丢失可复现参考和原始配音。`.gitattributes`关闭自动换行转换，防止换电脑checkout后原页、计划与时间线的字节哈希改变。

当前可用普通Git提交，完整参考库首传较大；频繁修改音视频时建议配置Git LFS，并先核对目标托管平台的LFS额度。当前本机未安装Git LFS，本轮没有伪装成已配置。Git备份不包含项目外API凭据和`.venv`；新机器照本文重建环境。源文件与当前采用资产入库；本地备份ZIP另存，避免把整个ZIP再提交造成双份体积。

用户只需提供私有仓库地址或在编辑器选择仓库，由Codex处理初始化、版本记录和推送；没有地址时先完成本地准备，不猜远端、不创建公开仓库。此前ZIP是当时验收快照，Git后续提交包含新增的上传准备配置。

## 独立意味着什么

工作室是旧项目旁边的独立目录。可运行工具、默认配置、音源、开放字体、水印、参考视频和必要数据均在本目录；不把旧项目路径作为运行输入。旧资料来历会记录在迁移清单中，那是溯源文字，不是运行依赖。原萧山工程没有被移动、删改或覆盖。

本机 `.venv` 是新建Python环境；基础工具不需要剪辑软件、DAW、浏览器编辑器或FluidSynth。用Python、Pillow/NumPy、FFmpeg、PyAV和本地音源完成。`requirements.txt`是兼容范围，`requirements.lock.txt`记录本次实装版本；新系统先用 `python3 工具/bootstrap.py`，由Codex处理环境问题。虚拟环境本身不适合跨机器直接复制，应重新建立。

独立ASR和自动浏览器检查在 `requirements-optional.txt`；按需安装和下载相应模型/浏览器，不把“未装可选检查器”伪装成已完成人工试听。基础合成和解码不依赖它们。

## 凭据与付费服务

本机旧项目的现有MiniMax凭据已迁移到项目外的用户私有配置，权限仅当前用户可读写。工作室CLI执行 `tts`/`video` 时把它读入 `MINIMAX_API_KEY` 环境变量；凭据从不进入包内。直接调用子工具时由调用环境提供变量。

macOS私有位置：`~/Library/Application Support/啊子牙视频工作室/credentials.json`；其他系统默认 `~/.config/aziyah-video/credentials.json`（尊重XDG_CONFIG_HOME）。文件可含 `MINIMAX_API_KEY`，但不要把具体值写进聊天、文档或调用记录。换电脑需要重新配置账号凭据，不可能随项目无密钥地恢复账户权限。

初次迁移没有提交新配音/AI视频生成；2026-10-26本轮标准复核经用户授权，真实测试默认TTS和AI视频各一次，记录见`检查/工作室验收.json`。已验证这两种调用当时成功，不代表以后余额、模型权限或服务状态不变。新一期按实际需要与已有授权核对服务，CLI不会偷偷提交试单。

## 入口和文件关系

`工具/studio.py doctor`检查本地依赖和必要资产；`new`复制单期模板；`source`把现有资料复制到本期并记来源和哈希；`snapshot`保存改动前的文本/状态/时码；`audio/voice/tts/bridge/animation/highlight/render/video`转发到相应工具。用户只需自然语言提出任务，命令由Codex运行。

时间线以实音为准：自然段录音 → 整帧补齐后的段落时框 → 全局字幕/章节 → 镜头表 → 完整混音 → 媒体manifest。采用完整语义句，禁止把供应商偏早的时码直接作为字音切口。任何段落加减时，都要同步后续字幕、镜头、章节、来源和水印位置。

## 快照与重做范围

本期的原始资料保留只读原件；裁切/强调/字幕/混音/输出另存新路径。`studio.py snapshot`保存文本和元数据，不是所有大媒体的备份。旧成片保留在导出历史中；替换素材前需把旧素材保留到归档或另名版本，不把一份哈希报告误当成备份文件。

局部改配音，先尝试保留原时框且只补尾静音；超过时框则诚实重排，不能拉快声音。画面注释变化重编码受影响输出；声音变化重混受影响章节并重新桥接，再生成两版。别用旧脚本重建整条时间线而抹掉新停顿。

`状态.json`应记：最后用户要求、实际完成项、待办、运行任务ID/进程/日志、已确认稿、当前预算授权和最新成片。工具超时并不证明任务失败；先看任务状态/输出文件与哈希，不自动重复付费提交。

## 搬家验收

1. 在新路径重建环境，运行doctor；任何运行代码中的旧绝对路径都要移除。
2. 对参考库清单做SHA核对，重渲一段星月/机制动画、重编一段音乐。
3. 从本地音频+画面+字幕生成完整小样和两种版本，完整解码并检查水印/字幕/章节。
4. 浏览器实际打开入口，检查链接与播放器；核验报告写明是否真的做过搬迁测试，不能仅因为用了相对路径就声称测试通过。

交付备份包排除`.venv`、凭据、临时缓存和Python编译缓存；包含源码、配置、参考原件/许可和真实核验样品。保留可重建环境依赖表。

## 本次实际验证与可重复入口

2026-10-26，已把工作室复制到随机新路径，在同一台macOS上重新运行整段验收流程：从本地旁白编排开始，重渲1920×1080星月动画、重新作曲混音、输出19.12秒的B站与无个人水印两版。两版均478帧，实际音频包与解码样本一致。详情见 `检查/整项目迁移验收.json`。这次复用了工作室已安装的Python依赖，不代表在全新电脑或Windows上完成重装测试。

Codex可使用下面的本地命令重建；它们不调用付费生成：

```bash
.venv/bin/python 工具/重建验收样片.py
.venv/bin/python 工具/归档工作室.py
```

重建会保留此前的样片编排/混音和导出历史。备份工具生成ZIP，内含逐文件SHA清单，并检查ZIP完整性；备份排除构建缓存和重建历史，当前采用素材、参考原件与最终产物保留。`检查/归档记录.json`记录实际备份位置和哈希。

`工具/核验工作室入口.py`是可选Playwright检查，验证桌面/手机布局、视频规格、版本切换保持位置和章节跳转。本次用本机现有Playwright环境实际执行；制作工具本身和新工作室基础环境不依赖旧项目的浏览器检查环境。若未来需要重跑，安装 `requirements-optional.txt` 的浏览器依赖即可。
